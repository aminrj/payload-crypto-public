TRANS3 SMART ADMIN INTERFACE V3.0

Layer 3 In-Place Payload Encryptor — Operational Reference Guide

1. Technological Overview

TRANS3 is a smart cryptographic engine operating directly at the network layer (Layer 3). Unlike traditional VPN solutions, it encrypts only the payload without altering the transport protocol[cite: 8, 9, 18, 19]. A TCP packet remains a TCP packet on the wire; only the actual payload data disappears into the encryption[cite: 19, 20].

Criterion TRANS3 V3.0 (Layer 3) Classic VPN (IPsec / WireGuard)
Network Protocol Unchanged (TCP / UDP / ICMP) [cite: 12] Modified (Encapsulated) [cite: 12]
Virtual Interface None (Transparent) [cite: 12, 21] Required (tun0, wg0) [cite: 12]
Session / Handshake None (0 ms latency) [cite: 12, 23] Mandatory (100ms - 500ms) [cite: 12]
Cryptography 100% Symmetric (XChaCha20-Poly1305) Asymmetric + Symmetric [cite: 12]
Overhead Fixed +32 bytes Variable + Headers [cite: 12]

2. Cryptographic Architecture

Every single packet is encrypted in a completely independent fashion with a dynamically generated unique nonce[cite: 24, 107, 109]. With no sessions dynamically negotiated, dropped packets will never break or hang the network conduit[cite: 108].

Packet Format on the Network:

[ IP hdr ] [ L4 hdr ] [ ENCRYPTED PAYLOAD + SEQ ] [ MAC:16B ] [ RNONCE:8B ]
  • Confidentiality: XChaCha20 (Content becomes physically indecipherable)[cite: 110].
  • Integrity: Poly1305 MAC (16 bytes). Packets are instantly destroyed if the fingerprint is altered.
  • Anti-Replay: 4096-packet sliding window hidden within the encrypted payload.

4. Menu Options Details

Option 1: Initialize kernel engine

Starts the encryption engine by loading the xt_TRANS3 kernel module and adjusts the physical MTU to 1550 to absorb the encryption overhead.

[*] Analyzing system kernel... [+] Engine started successfully. MTU adjusted to 1550. Press Enter to continue...

Option 2: Security Key Management

Queries the local signature status or imports an external "Air-Gap" token to hermetically seal your private keys into the system memory[cite: 73, 74].

┌──────────────────────────────────────────┐ │ KEY SECURITY │ └──────────────────────────────────────────┘ a) Check local signature status b) Import external token (Air-Gap USB) Choice: a [+] Valid signature found. Press Enter to continue...

Option 3: Add an encryption rule

The core of the protection. Provide the target IP: all protocols targeting this specific remote equipment will instantly undergo cryptographic encapsulation[cite: 77, 80].

┌──────────────────────────────────────────┐ │ ADD L3 ENCRYPTION RULE │ └──────────────────────────────────────────┘ Target IP to encrypt: 192.168.1.50 [+] Rules added. Traffic to/from 192.168.1.50 is now encrypted (Layer 3). Press Enter to continue...

Option 4: Real-time Encryption Telemetry

Provides a detailed real-time report regarding the actual utilization of secured traffic (Outbound encrypted flows and Inbound decrypted flows)[cite: 83].

╔══════════════════════════════════════════════════════╗ ║ ENCRYPTION TELEMETRY ║ ╚══════════════════════════════════════════════════════╝ [ OUTBOUND FLOWS (ENCRYPTING --mode e) ] [TX] To: 192.168.1.50 | Proto: tcp | Encrypted: 120 pkts (15400) [ INBOUND FLOWS (DECRYPTING --mode d) ] [RX] From: 192.168.1.50 | Proto: tcp | Decrypted: 98 pkts (10240) Press Enter to continue...

Option 5: Lock system configuration

Enables service resilience. The routing matrix housing your protected IP targets is stored persistently (ROM write)[cite: 93]. Following any reboot, all tunnels will be securely re-established[cite: 94].

[*] Writing to system ROM... [+] Encryption rules permanently sealed. Press Enter to continue...

Option 6: Purge matrix

The absolute kill switch. Meticulously destroys all encrypted IP links and instantaneously reverts the machine back to standard "clear text" network mode[cite: 97].

[*] Purging encryption rules... [+] Network interface restored to Clear Text Mode (MTU 1500). Press Enter to continue...

Option 7: Exit

Closes the command-line administration assistant. You can choose to leave the encryption engine fully engaged and performant in the background[cite: 101, 104].

[?] Shutdown sequence: Keep encryption active in background? (Y/n): Y > Encryption active in background. Terminal disconnected.
